2. АЛГОРИТМ ИСПОЛЬЗОВАНИЯ (5 ШАГОВ)

ШАГ 1: Определите задачу
Чётко сформулируйте, что нужно получить. Примеры:
❌ "Помоги с кодом"
✅ "Нужен API-эндпоинт для авторизации по PIN"

ШАГ 2: Выберите промпт из нужного раздела
Откройте папку, соответствующую типу задачи:
Код → 1_РАЗРАБОТКА И КОД
ТЗ, инструкции → 2_ДОКУМЕНТАЦИЯ
Спринты, риски → 3_АНАЛИЗ И ПЛАНИРОВАНИЕ
Интерфейсы, CJM → 4_UX_UI ПРОЕКТИРОВАНИЕ
Питчи, демо → 5_КОММУНИКАЦИЯ И ПРЕЗЕНТАЦИИ
SQL, скрипты → 6_АВТОМАТИЗАЦИЯ И ОПТИМИЗАЦИЯ

ШАГ 3: Скопируйте промпт и заполните плейсхолдеры
Замените всё в [КВАДРАТНЫХ СКОБКАХ] на ваши данные.
Пример (промпт #1 из раздела "Разработка"):

Роль: Backend-разработчик (Node.js/Express)
Задача: Создай полный код для POST /api/auth
Требования:
- RESTful, идемпотентный
- Защита от краевых случаев (try-catch, валидация)
- ENV-переменные, не hardcoded
- Формат ответа: JSON
Вывод: один файл с меткой «создать» или «заменить»

ШАГ 4: Отправьте промпт Qwen
Вставьте заполненный промпт в чат. Qwen ответит структурированно.

ШАГ 5: Уточняйте при необходимости
Если результат не идеален:
Добавьте контекст ("У нас уже есть lib/store.js v14")
Уточните ограничения ("Только для 2-3 пользователей")
Попросите альтернативу ("Предложи вариант без JWT")


3. ПРИМЕРЫ ИСПОЛЬЗОВАНИЯ

Пример А: Разработка (раздел 1)
Задача: Создать эндпоинт для импорта CSV в WMS.

Промпт:
Роль: Backend-разработчик (Node.js/Express)
Задача: Создай полный код для POST /api/import
Требования:
- RESTful, идемпотентный
- Защита от краевых случаев (try-catch, валидация)
- ENV-переменные, не hardcoded
- Формат ответа: JSON
- Лимит: 2000 строк
- CSV с BOM \uFEFF для Excel
Вывод: один файл api/import.js с меткой «создать»

Результат: Готовый файл с обработкой ошибок, валидацией и логированием.

Пример Б: Документация (раздел 2)
Задача: Написать ТЗ для функции "Точка заказа".

Промпт:
Роль: Системный аналитик
Задача: ТЗ для функции "Точка заказа"
Структура:
- Цель (1 предложение)
- Требования (функциональные/нефункциональные)
- Ограничения (технические, сроки)
- Критерии приёмки (тестируемые)
Вывод: Markdown, готовый для Jira/Notion
Контекст: daysLeft=stock/norm, порог 7 дней, recommended=norm*14−stock

Результат: Структурированное ТЗ с критериями приёмки.

Пример В: UX (раздел 4)
Задача: Спроектировать экран уведомлений для "Ожившей Истории".

Промпт:
Роль: UX/UI Designer
Задача: Спроектируй экран "Уведомления"
Пользовательская цель: Ученик видит новые эпохи и достижения
Элементы:
- Иерархия информации
- CTA (главная кнопка)
- Состояния (пусто, загрузка, ошибка)
Вывод: описание + wireframe (текстовый)
Контекст: Нижняя навигация (шлем/свиток/колокол), активная иконка — золото

Результат: Описание экрана с состояниями и навигацией.

4. КАК АДАПТИРОВАТЬ ПРОМПТЫ
Правило 1: Добавляйте контекст проекта
Чем больше фактов, тем точнее ответ.

Плохо: Роль: Backend-разработчик
       Задача: API для логина
	   
Хорошо: Роль: Backend-разработчик (Node.js/Express)
        Задача: POST /api/auth для WMS
        Контекст: 3 роли (работник/директор/бухгалтер), PIN-код, Vercel + Blob
        Требования: идемпотентность, защита от минуса, ENV-переменные

Правило 2: Указывайте ограничения
Ограничения помогают избежать "воды" и нереалистичных решений.
Добавьте в промпт:
"Только для 2-3 пользователей"
"Без внешних мессенджеров"
"Работает офлайн"
"Бюджет: 0 рублей (только бесплатные сервисы)"
Правило 3: Требуйте конкретный формат вывода
Вместо "сделай хорошо" → "таблица с колонками X, Y, Z".
Примеры форматов:
"Таблица: Задача | Оценки | Риски | Приоритет"
"Markdown с заголовками H2 и H3"
"JSON-схема с полями id, name, status"
"Один файл с меткой 'создать' или 'заменить'"
Правило 4: Используйте мастер-шаблоны для сложных задач
Если микро-промпта недостаточно, откройте УНИВЕРСАЛЬНЫЙ МАСТЕР-ШАБЛОН ПРОМПТА.md и заполните все 5 разделов.

5. СОВЕТЫ ПО ПОВЫШЕНИЮ КАЧЕСТВА

Совет 1: Задавайте роль конкретно
❌ "Ты — разработчик"
✅ "Ты — Senior Backend-разработчик с опытом в Node.js и Vercel"

Совет 2: Просите оценку уверенности
Добавьте в конец промпта: "Оцени уверенность в ответе по шкале 1-10 и укажи, чего не хватает для 10/10"

Совет 3: Требуйте альтернативы
Предложи 2 варианта решения:
1. Консервативный (минимум рисков)
2. Инновационный (максимум эффективности)

Совет 4: Используйте Chain of Thought
Для сложных задач добавьте: "Используй метод рассуждения "Chain of Thought" — проговори логические шаги перед финальным выводом"

Совет 5: Запрещайте галлюцинации! "Если информации недостаточно, НЕ выдумывай факты. Остановись и задай 1-3 уточняющих вопроса"
